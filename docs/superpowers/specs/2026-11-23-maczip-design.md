# 맥집(MacZip) 설계 문서

> 2026-11-23: 사용자 요청으로 앱 이름을 "Maczip"에서 "맥집(MacZip)"으로 바꿨다. 아래 본문의 Maczip은 맥집과 같은 앱을 가리킨다. 번들 식별자 `dev.maczip.app`은 기존 설치·서비스 등록과의 연속성을 위해 유지한다.

작성일: 2026-11-23 / 상태: 승인됨 (dmg 배포 항목 추가 후)

## 1. 의도와 이유

맥의 기본 보관 유틸리티로 만든 zip을 윈도우 사용자에게 보내면 **한글 파일명이 깨지고**, 압축할 때 **비밀번호를 걸 수 없다**. Maczip은 이 두 가지를 해결하는 맥용 zip 전용 압축·해제 앱이다.

파일명이 깨지는 원인은 맥이 파일명을 자모가 분리된 형태(NFD)로, UTF-8 플래그 없이 저장하기 때문이다. 이 때문에 윈도우 쪽 프로그램이 이름을 잘못 해석한다. 반대로 윈도우에서 만든 zip은 한글 이름이 CP949로 저장된 경우가 많아 맥에서 열면 깨진다. 앱은 두 방향을 모두 처리한다.

사용자: 본인과 지인. 개인 용도다.

## 2. 목표 / 비목표 / 안티목표

**목표**
- 압축: 파일·폴더를 zip으로 만든다. 윈도우(탐색기, 반디집, 7-Zip)에서 한글 파일명이 깨지지 않아야 한다.
- 압축 시 선택적으로 비밀번호를 건다. (2026-11-23 변경, 사용자 요청) 암호 방식은 압축할 때 **AES-256(기본) / ZipCrypto** 중에서 고른다.
- 해제: zip을 푼다. 비밀번호가 걸린 zip도 푼다. 파일명 인코딩을 자동으로 판별한다.
- 창 하나짜리 앱에서 파일을 끌어다 놓는 방식으로 쓴다.

**비목표**
- zip 외 포맷(7z, rar, tar, gz 등)의 압축·해제
- Finder 우클릭 메뉴 확장, CLI
- 앱스토어 배포, 공증(notarization)
- 4GB 초과 파일(ZIP64), 분할 압축, 압축 파일 내용 미리보기

**안티목표 (기술적으로 동작해도 실패로 보는 경우)**
- 윈도우에서 열었을 때 한글 이름이 하나라도 깨지는 zip을 만드는 것
- 비밀번호가 프로세스 인자, 로그, 임시 파일 등에 남는 것
- 해제 중 압축 파일 안의 경로 때문에 지정한 폴더 밖에 파일이 써지는 것(zip-slip)
- 압축을 풀었는데 조용히 손상된 파일이 만들어지는 것(CRC 불일치를 모르고 넘어감)

## 3. 제약

- macOS 전용, SwiftUI 앱. 외부 라이브러리 없이 시스템 zlib(deflate/inflate)만 사용한다.
- 비밀번호 방식은 ZipCrypto(사용자 결정). (2026-11-23 변경, 사용자 요청) 앱 화면의 ZipCrypto 암호 강도 경고 문구는 표시하지 않는다. 한계는 README·dmg 안내 파일에만 적는다.
- 개인 용도 로컬 빌드(서명은 ad-hoc 수준)다. Apple 개발자 계정이 없으므로 서명·공증은 하지 않는다.

## 4. 접근 방식 (검토한 안)

| 안 | 내용 | 장단점 |
|----|------|--------|
| **A. 순수 Swift + 직접 만든 zip 처리부 (선택)** | SwiftUI 앱 + 시스템 zlib 위에 zip 읽기·쓰기·ZipCrypto를 직접 구현 | 의존성이 없고 파일명 처리를 완전히 제어한다. 형식 코드를 직접 짜야 하므로 교차 검증 테스트로 보완한다. |
| B. Swift + minizip-ng | C 라이브러리를 연결 | 호환성은 좋으나 빌드 연결이 번거롭고, 인코딩 판별은 어차피 직접 만들어야 한다. |
| C. 시스템 zip/unzip 호출 | 명령어 래핑 | 비밀번호가 프로세스 인자에 노출되고 파일명 제어가 어려워 제외했다. |

사용자가 A를 선택했다.

## 5. 구조

두 부분으로 나눈다. UI 없이 테스트할 수 있는 코어 라이브러리와, 그 위의 얇은 앱이다.

**MaczipCore (UI 없음)**
- `ZipWriter`: 항목을 순서대로 쓰고 중앙 디렉터리를 만든다. deflate 또는 store.
- `ZipReader`: 중앙 디렉터리를 읽어 항목 목록을 만들고, 항목별로 스트리밍 해제한다.
- `ZipCrypto`: 암호화·복호화(키 3개 갱신 방식, 12바이트 헤더).
- `FilenameCodec`: 이름 정규화와 인코딩 판별(6절).
- `PathSafety`: 해제 시 경로 검증(7절).

**Maczip 앱**
- 창 하나. 파일을 끌어다 놓는 영역, 비밀번호 입력란(압축 시), 진행 표시, 결과 메시지로 구성한다.

## 6. 파일명 처리 (이 프로그램의 핵심)

**압축 시**
- 이름을 NFC(합쳐진 한글)로 정규화하고 UTF-8로 저장하며, 일반 목적 비트 11(UTF-8 이름 플래그)을 켠다.
- `.DS_Store`, `__MACOSX/`, `._*`(AppleDouble) 항목은 넣지 않는다. 윈도우에서 불필요한 파일로 보이기 때문이다.

**해제 시 인코딩 판별 순서**
1. UTF-8 플래그(비트 11)가 켜져 있으면 UTF-8로 읽는다.
2. Info-ZIP Unicode Path 확장 필드(0x7075)가 있으면 그 이름을 쓴다(CRC 일치 시).
3. 플래그가 없고 바이트열이 유효한 UTF-8이면 UTF-8로 읽는다(맥 기본 유틸리티가 만든 파일).
4. 그렇지 않으면 CP949로 해석을 시도하고, 모든 항목 이름이 문제없이 디코드되면 채택한다.
5. 그것도 실패하면 CP437로 읽는다(zip 규격 기본값).

판별은 항목마다 하지 않고 **압축 파일 단위로 한 번** 한다. 항목마다 달라지면 같은 파일 안에서 이름이 섞이기 때문이다. 해제 결과 이름은 NFC로 정규화한다.

## 7. 해제 시 안전·정확성 규칙

- 절대 경로, `..` 포함 경로, 드라이브 문자(`C:`)가 들어간 이름은 거부하거나 안전하게 정리한다. 지정한 폴더 밖에는 절대 쓰지 않는다.
- 심볼릭 링크 항목은 만들지 않는다. 건너뛰고 결과 메시지에 건수를 알린다.
- 해제한 모든 파일은 CRC32를 검증하고, 불일치하면 해당 파일을 실패로 처리한다.
- 비밀번호 확인: ZipCrypto 헤더의 검사 바이트로 1차 판별하고(오탐 약 1/256), 최종적으로는 CRC로 확인한다. 틀린 비밀번호는 "비밀번호가 맞지 않음"으로 명확히 알리고 부분 결과를 남기지 않는다.
- 압축 비율이 비정상적으로 큰 항목(zip bomb)은 해제 전에 총 해제 크기를 계산해 확인 단계를 둔다. 한도 값은 구현자가 정한다.
- 출력 위치에 같은 이름이 있으면 덮어쓰지 않고 `이름 2`처럼 번호를 붙인다.

## 8. 앱 동작

- 끌어다 놓은 항목이 `.zip` 하나면 **해제**, 그 외(파일·폴더 하나 이상)는 **압축**으로 자동 판단한다. 판단 결과를 화면에 분명히 표시한다.
- (2026-11-23 추가, 사용자 요청) Finder 우클릭 메뉴 맨 아래에 **"Maczip에서 열기"**(macOS 서비스)를 추가한다. 파일·폴더, 여러 개 선택 모두 지원하며 동작은 끌어다 놓기와 같다. (2026-11-23 변경, 사용자 요청) 메뉴 이름을 **"맥집에서 압축하기"**로 바꾸고, .zip 파일을 골라도 풀지 않고 **항상 압축**한다. 서비스로 앱이 실행돼도 창이 뜨도록 메인 창은 AppDelegate가 직접 만들고, 창을 닫으면 앱을 종료한다.
- (2026-11-23 추가, 사용자 요청) 첫 화면을 클릭하면 파일 선택 창이 열리고, 파일과 폴더를 여러 개 골라 한꺼번에 압축한다. 선택 창에서 고른 항목은 `.zip` 파일이어도 압축한다.
- 압축: 비밀번호는 **두 번 입력**(비밀번호, 비밀번호 확인)하고 두 값이 같을 때만 압축할 수 있다. (2026-11-23 추가, 사용자 요청) 압축 비밀번호에는 **영문·숫자·키보드 기호(ASCII 0x20–0x7E)만** 쓸 수 있고 한글 등은 입력 즉시 지운다. 비밀번호 칸에 들어가면 키보드가 한글 등일 때 **영문 자판으로 자동 전환**하고, 칸을 벗어나면 원래 자판으로 되돌린다. 해제용 비밀번호 창은 한글 비밀번호 zip을 열 수 있도록 제한하지 않는다. 둘 다 비워 두면 암호화하지 않는다. 비밀번호를 입력하면 ZipCrypto로 암호화한다. 결과는 첫 항목과 같은 폴더에 만든다. 단일 항목이면 `그 이름.zip`, 여러 개면(선택 창·끌어다 놓기 모두) **`archive.zip`**(사용자 요청, 이미 있으면 `archive 2.zip`).
- 해제: 비밀번호가 필요하면 입력창을 띄운다. 결과는 원본 zip과 같은 폴더의 `zip이름/` 폴더에 푼다.
- 압축·해제는 백그라운드에서 실행하고, UI는 멈추지 않으며 취소할 수 있다.
- UI 문구는 한국어다.

## 9. 파일 형식 지원 범위

- 쓰기: deflate(method 8), store(method 0). 파일 확장자·크기상 이득이 없으면 store를 쓰는 판단은 구현자 재량이다.
- 읽기: deflate와 store만 지원한다. 그 외 방식은 "지원하지 않는 압축 방식"으로 명확히 실패한다.
- 암호화된 항목: ZipCrypto와 WinZip AES(AE-1/AE-2, 128/192/256비트)를 지원한다. 쓰기는 AE-2·AES-256(메서드 99 + 0x9901 확장 필드, PBKDF2-HMAC-SHA1 1000회, AES-CTR, HMAC-SHA1 인증 코드 10바이트). 0x9901 정보가 없거나 강도를 알 수 없는 AES 항목은 "AES 암호화는 지원하지 않음"으로 알린다.
- 유닉스 권한(실행 비트)은 외부 속성에 저장하고 해제 시 복원한다. 날짜는 DOS 시간을 쓴다.
- 데이터 디스크립터(비트 3)로 크기가 뒤에 오는 항목도 읽을 수 있어야 한다.

## 10. 검증 방법

자동 테스트(코어 라이브러리):
- Maczip이 만든 zip을 `/usr/bin/unzip`, Python `zipfile`로 열어 내용과 비밀번호가 맞는지 확인한다.
- `/usr/bin/zip`, Python으로 만든 zip(비밀번호 포함)을 Maczip이 열어 내용이 같은지 확인한다.
- 한글 이름 + NFD/NFC, CP949로 저장된 이름, UTF-8 플래그 유무 조합 각각을 해제해 이름이 올바른지 확인한다.
- 악의적 경로(`../x`, `/etc/x`), 틀린 비밀번호, 손상된 CRC에 대한 거부 동작을 확인한다.
- 빈 폴더, 빈 파일, 깊은 폴더 구조, 큰 파일(수백 MB, 메모리 사용량이 파일 크기에 비례하지 않을 것)을 확인한다.

수동 확인(인수 기준): 본인이 윈도우 PC나 윈도우 VM에서 Maczip이 만든 zip(비밀번호 있음/없음)을 탐색기와 반디집으로 열어 한글 이름과 비밀번호 입력이 정상인지 확인한다. 이 항목은 이 환경에서 자동화할 수 없다.

## 11-1. 배포: 서명 없는 dmg

- 스크립트 한 줄(예: `scripts/make-dmg.sh`)로 앱을 빌드하고 `Maczip.dmg`를 만든다. 맥 기본 도구(`hdiutil`)만 쓴다.
- dmg 안에는 `Maczip.app`, `Applications` 폴더 바로가기, 처음 여는 방법 안내(한국어 텍스트 파일)를 넣는다.
- 서명·공증을 하지 않으므로 다른 맥에서는 처음 실행할 때 "확인되지 않은 개발자" 경고가 뜬다. 안내 파일에 우클릭 → 열기(또는 시스템 설정 → 개인정보 보호 및 보안에서 허용) 방법을 적는다.
- 앱 번들은 ad-hoc 서명(`codesign -s -`)만 한다. 이는 Apple Silicon 맥에서 앱이 실행되기 위한 최소 조건이다.
- 빌드 결과물은 Apple Silicon과 Intel을 모두 지원하는 유니버설 바이너리로 만드는 것을 목표로 하되, 어려우면 Apple Silicon만 지원해도 된다(구현자 판단, 결과를 보고할 것).

## 12. 설계자(Claude)가 정한 항목 — 확인 필요

사용자와 합의한 내용이 아니라 설계 과정에서 제가 채운 값이다.

1. 압축 시 이름을 NFC + UTF-8 플래그로 저장한다.
2. `.DS_Store`, `__MACOSX`, `._*` 항목을 압축에서 제외한다.
3. 심볼릭 링크는 압축·해제 모두 따라가지 않고 건너뛴다.
4. 해제 인코딩 판별은 압축 파일 단위로 한 번 하고, 순서는 UTF-8 플래그 → 0x7075 → 유효한 UTF-8 → CP949 → CP437이다.
5. 해제 결과 폴더는 `zip이름/`이고, 이름이 겹치면 번호를 붙인다.
6. 끌어다 놓은 항목으로 압축·해제를 자동 판단한다(별도 모드 전환 버튼 없음).
7. 대상 macOS 버전은 14 이상으로 잡는다.
8. 앱 UI는 한국어다.
9. dmg의 구성(앱 + Applications 바로가기 + 한국어 안내 파일)과 유니버설 바이너리 목표는 제가 정했다. dmg 배포와 서명 없음 자체는 사용자가 결정했다.
