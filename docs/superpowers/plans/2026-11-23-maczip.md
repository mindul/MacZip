# Maczip 구현 계획

> **실행자에게:** 필수 서브스킬: `superpowers:subagent-driven-development`(권장) 또는 `superpowers:executing-plans`로 태스크 단위로 구현한다. 단계는 체크박스(`- [ ]`)로 추적한다.

**목표:** 윈도우에서 한글 파일명이 안 깨지는 zip을 만들고(선택적 ZipCrypto 비밀번호), 인코딩을 자동 판별해 zip을 푸는 맥용 SwiftUI 앱과, 서명 없는 dmg 설치 파일을 만든다.

**구조:** UI 없는 코어 라이브러리 `MaczipCore`(zip 읽기·쓰기·ZipCrypto·파일명 처리)와 그 위의 얇은 SwiftUI 앱 `MaczipApp`, 그리고 테스트 러너 실행 파일 `MaczipChecks`로 나눈다. 모두 SwiftPM 하나로 빌드하고, 앱 번들과 dmg는 셸 스크립트로 조립한다.

**기술 스택:** Swift 6.2(언어 모드 5), SwiftUI, 시스템 zlib, `hdiutil`/`codesign`. 외부 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-11-23-maczip-design.md`

## 환경 사실 (계획 작성 중 실측)

- 이 맥에는 **Xcode가 없고 Command Line Tools만 있다.** `xcodebuild`를 쓸 수 없다.
- **XCTest와 Swift Testing 모듈이 모두 없다.** 그래서 `swift test`는 쓸 수 없고, 직접 만든 **테스트 러너 실행 파일 `MaczipChecks`**를 `swift run MaczipChecks`로 실행한다. (Xcode를 설치하면 XCTest로 옮길 수 있지만 필수는 아니다.)
- `swift build -c release`는 동작한다(SwiftUI + zlib 링크 확인함). **`--arch arm64 --arch x86_64`(유니버설)는 xcbuild가 없어 실패한다.** 설계 문서가 허용한 대로 Apple Silicon 전용으로 빌드하고 결과 보고에 명시한다.
- 사용 가능: `/usr/bin/zip`, `/usr/bin/unzip`, `hdiutil`, `codesign`, `python3`(3.15). CPU `arm64`, macOS 27.0.1.
- 프로젝트 폴더는 git 저장소가 아니다. 태스크 1에서 `git init` 한다.

## 전역 제약 (설계 문서에서 그대로 옮김)

- macOS 전용, SwiftUI 앱. **외부 라이브러리 없이 시스템 zlib(deflate/inflate)만 사용한다.**
- 비밀번호 방식은 **ZipCrypto**. 앱 안에 암호 강도가 약하다는 점을 한 줄로 알린다.
- 지원 포맷은 **zip 하나**(압축·해제 모두). 쓰기는 deflate/store, 읽기는 deflate/store만. AES 항목은 "AES 암호화는 지원하지 않음"으로 알린다.
- 압축 시 이름은 **NFC + UTF-8 플래그(비트 11)**. `.DS_Store`, `__MACOSX/`, `._*`는 넣지 않는다.
- 해제 시 인코딩 판별 순서: **UTF-8 플래그 → 0x7075 → 유효한 UTF-8 → CP949 → CP437**. 압축 파일 단위로 한 번만 판별하고, 결과 이름은 NFC.
- 해제 안전: 절대 경로·`..`·드라이브 문자 거부(폴더 밖에 쓰지 않음), 심볼릭 링크는 건너뛰고 건수를 알림, 모든 파일 CRC32 검증, 틀린 비밀번호는 명확히 알리고 부분 결과를 남기지 않음, 같은 이름은 덮어쓰지 않고 `이름 2`로 번호를 붙임.
- 비밀번호를 프로세스 인자·로그·임시 파일에 남기지 않는다.
- 4GB 초과(ZIP64)는 범위 밖이며 명확한 오류로 실패한다.
- 대상 macOS **14 이상**. UI 문구는 **한국어**.
- 압축·해제는 백그라운드에서 실행하고 UI는 멈추지 않으며 취소할 수 있다.
- 서명·공증은 하지 않는다. 앱 번들은 ad-hoc 서명(`codesign -s -`)만 한다.

## Review Focus

스펙이 암시하지만 개별 태스크의 기본 테스트가 다루지 않는 입력들이다. 각 항목의 테스트는 해당 코드를 가진 태스크에 들어 있다.

1. **한글 등 비ASCII 비밀번호** — 윈도우 도구마다 비밀번호 바이트 인코딩이 다르다. 사용자가 같은 글자를 입력하면 UTF-8로 만든 zip도, CP949로 만든 zip도 열려야 한다. (태스크 2, 7)
2. **출력 zip이 입력 폴더 안에 생기는 경우** — 폴더를 압축하면 만들던 zip 자신이 들어가 무한히 커지면 안 된다. (태스크 8)
3. **zip 안의 중복 이름 / 대소문자만 다른 이름** — APFS는 기본이 대소문자 무시다. 하나가 다른 하나를 조용히 덮어쓰면 안 된다. (태스크 8)
4. **쓸 수 없는 출력 위치** — 읽기 전용 폴더, 권한 없음. 앱이 죽지 않고 오류를 알리며 반쪽짜리 `.zip`을 남기지 않아야 한다. (태스크 8)
5. **빈 zip(항목 0개)과 빈 폴더만 있는 입력** — 크래시 없이 처리하고, 빈 폴더는 해제 후에도 빈 폴더로 남아야 한다. (태스크 7, 8)

### Task 2: ZipError, CRC32, ZipCrypto, 비밀번호 후보

**Files:**
- Create: `Sources/MaczipCore/{ZipError,CRC32,ZipCrypto}.swift`, `Sources/MaczipChecks/ZipCryptoChecks.swift`
- Modify: `Sources/MaczipChecks/main.swift`(suite 등록)

**Interfaces:**
- Produces:
  - `public enum ZipError: Error, Equatable { case notAZip, corrupt(String), unsupportedMethod(UInt16), unsupportedAES(entry: String), passwordRequired, wrongPassword, crcMismatch(entry: String), unsafePath(String), tooLarge(String), cancelled, io(String) }`
  - `public enum CRC32 { public static func update(_ crc: UInt32, _ data: Data) -> UInt32; public static func checksum(_ data: Data) -> UInt32 }` — `update`의 시작값은 0.
  - `public struct ZipCryptoEncryptor { public init(password: [UInt8], checkByte: UInt8, random: [UInt8]? = nil); public let header: [UInt8]; public mutating func encrypt(_ data: inout Data) }` — `header`는 12바이트이며 마지막 바이트가 `checkByte`. `random`이 nil이면 암호학적 난수 11바이트.
  - `public struct ZipCryptoDecryptor { public init(password: [UInt8], header: [UInt8]); public let checkByte: UInt8; public mutating func decrypt(_ data: inout Data) }` — `checkByte`는 복호화된 헤더의 마지막 바이트.
  - `public enum ZipPassword { public static func candidates(_ password: String) -> [[UInt8]] }` — `[UTF-8 바이트]`, 그리고 CP949로 표현 가능하고 UTF-8과 다르면 `[CP949 바이트]`를 뒤에 추가. 모두 ASCII면 후보는 하나.

- [ ] **Step 1: 실패하는 점검 작성** (`zipCryptoChecks`)
  - `CRC32.checksum(Data("123456789".utf8)) == 0xCBF43926`
  - `update`를 두 조각으로 나눠 호출한 결과 == 한 번에 `checksum`한 결과
  - 암호화 후 복호화하면 원문(빈 데이터, 1바이트, 100KB 각각), 올바른 비밀번호면 `decryptor.checkByte == 지정한 checkByte`
  - 틀린 비밀번호의 `checkByte`가 **다른 값**임을 서로 다른 비밀번호 20개로 확인(전부 같을 수는 없다. 최소 1개는 달라야 함)
  - 교차 검증: `py`로 `zipfile._ZipDecrypter(b"pw")`가 Maczip이 만든 `header + 암호문`을 복호화한 결과가 원문과 같음
  - `ZipPassword.candidates("abc") == [[0x61,0x62,0x63]]`, `candidates("한글")`은 길이 2이고 첫 후보가 UTF-8 바이트(6바이트), 둘째가 CP949 바이트(4바이트)
  - **(Review Focus 1)** `candidates("🙂")`처럼 CP949로 표현 불가능한 글자는 후보가 UTF-8 하나뿐
- [ ] **Step 2: 실패 확인** — Run: `swift run MaczipChecks ZipCrypto` / Expected: 컴파일 오류(타입 없음).
- [ ] **Step 3: 구현** — `CRC32`는 zlib `crc32`. ZipCrypto는 PKWARE 표준(키 3개 `0x12345678, 0x23456789, 0x34567890`, CRC 표로 갱신). CP949 변환은 `CFStringEncodings.dosKorean` → `CFStringConvertEncodingToNSStringEncoding`으로 `String.data(using:)`를 쓰고 `allowLossyConversion: false`.
- [ ] **Step 4: 통과 확인** — Run: `swift run MaczipChecks ZipCrypto` / Expected: `ALL PASSED`.
- [ ] **Step 5: 커밋** — `git add -A && git commit -m "feat: CRC32와 ZipCrypto"`

### Task 3: FilenameCodec (이름 정규화·인코딩 판별)

**Files:**
- Create: `Sources/MaczipCore/FilenameCodec.swift`, `Sources/MaczipChecks/FilenameCodecChecks.swift`

**Interfaces:**
- Consumes: `CRC32.checksum`
- Produces:
  - `public enum NameEncoding: Equatable { case utf8, cp949, cp437 }`
  - `public struct RawEntryName { public init(bytes: [UInt8], utf8Flag: Bool, unicodePath: (crc: UInt32, name: String)?) }`
  - `public enum FilenameCodec { public static func normalizeForArchive(_ name: String) -> String` (NFC); `public static func chooseEncoding(_ names: [RawEntryName]) -> NameEncoding`; `public static func decode(_ name: RawEntryName, using: NameEncoding) -> String`(NFC 결과) `}`

규칙: `chooseEncoding`은 플래그가 켜진 이름이 하나라도 있거나 모든 이름이 유효한 UTF-8이면 `.utf8`(순수 ASCII 포함). 아니면 모든 이름이 CP949로 디코드되면 `.cp949`, 아니면 `.cp437`. `decode`는 `unicodePath`가 있고 그 `crc`가 `CRC32.checksum(원본 바이트)`와 같으면 그 이름을 우선한다. 판별 불가·디코드 실패한 이름이 있어도 `decode`는 항상 문자열을 반환한다(CP437은 전 바이트가 매핑됨).

- [ ] **Step 1: 실패하는 점검 작성**
  - `normalizeForArchive("한글.txt")`를 NFD로 만든 입력도 결과가 NFC(`unicodeScalars.count`가 NFC 쪽과 같음)
  - 플래그 켜진 UTF-8 → `.utf8`, 플래그 없는 NFD UTF-8(맥 기본 유틸리티 형태) → `.utf8`, 플래그 없는 CP949 바이트(`"한글.txt"`를 CP949로 인코딩) → `.cp949`, 순수 ASCII → `.utf8`
  - 항목 3개 중 하나만 CP949 전용 바이트여도 전체 판별이 `.cp949`이고, 세 항목 모두 올바르게 디코드됨(항목마다 따로 판별하지 않음)
  - CP949도 UTF-8도 아닌 바이트(`[0xFF, 0xFE, 0x80]`) → `.cp437`이며 `decode`가 비어 있지 않은 문자열을 반환
  - `unicodePath` crc가 맞으면 그 이름 사용, 틀리면 무시
- [ ] **Step 2: 실패 확인** — Run: `swift run MaczipChecks FilenameCodec` / Expected: 컴파일 오류.
- [ ] **Step 3: 구현** — UTF-8 검증은 `String(validatingUTF8:)`(또는 `String(bytes:encoding:.utf8)`), CP949는 태스크 2와 같은 `dosKorean`, CP437은 `CFStringEncodings.dosLatinUS`.
- [ ] **Step 4: 통과 확인** — Run: `swift run MaczipChecks FilenameCodec` / Expected: `ALL PASSED`.
- [ ] **Step 5: 커밋** — `git add -A && git commit -m "feat: 파일명 인코딩 판별"`

### Task 5: RawDeflater / RawInflater

**Files:**
- Create: `Sources/MaczipCore/Deflate.swift`, `Sources/MaczipChecks/DeflateChecks.swift`

**Interfaces:**
- Consumes: `ZipError`
- Produces:
  - `public final class RawDeflater { public init(level: Int32 = 6); public func write(_ chunk: Data, sink: (Data) throws -> Void) throws; public func finish(sink: (Data) throws -> Void) throws }`
  - `public final class RawInflater { public init(); public func write(_ chunk: Data, sink: (Data) throws -> Void) throws; public var isFinished: Bool { get } }`

둘 다 zip용 **raw deflate**(`windowBits = -15`)를 쓰고 청크 단위 스트리밍이다(전체를 메모리에 올리지 않음). inflate 오류나 스트림 끝 이후 남은 데이터는 `ZipError.corrupt("inflate")`.

**Files:**

동작(스펙 7·8절):
- `compress`: 출력은 **첫 입력과 같은 폴더**. 이름은 입력이 하나면 `<이름>.zip`(파일은 확장자를 유지해 `보고서.hwp.zip`, 폴더는 `폴더.zip`), 둘 이상이면 `보관.zip`. 같은 이름이 있으면 `UniqueName`. 폴더는 재귀 순회하며 `<루트이름>/…` 항목을 만든다. 빈 폴더는 디렉터리 항목으로 넣는다. `.DS_Store`, `__MACOSX`, `._*`는 제외. 심볼릭 링크는 따라가지 않고 `skippedSymlinks`로 센다. **출력 zip 파일은 순회에서 제외**한다. 입력 루트 이름이 (대소문자 무시) 겹치면 뒤쪽에 ` 2`를 붙인다. 실패·취소 시 만들다 만 `.zip`을 삭제한다.
- `inspect`: 비밀번호 없이 중앙 디렉터리만 읽는다. 앱은 `totalUncompressedBytes > confirmBytes`이거나 (압축 비율 > 1000 이면서 총 크기 > 1GiB)일 때 사용자에게 확인을 받는다. 이 판단은 앱(태스크 9)이 하고 `inspect`는 값만 돌려준다.
- `extract`: 출력 폴더는 zip과 같은 폴더의 `<zip이름 − .zip>/`(겹치면 `UniqueName`). **같은 부모 폴더의 숨김 임시 폴더**(`.<이름>.maczip-tmp`)에 먼저 풀고 성공하면 최종 이름으로 이동한다. 비밀번호 오류·취소·치명적 오류면 임시 폴더를 통째로 삭제하고 던진다. 암호화 항목이 있는데 `password == nil`이면 **아무것도 쓰기 전에** `passwordRequired`. 이름이 `PathSafety`에서 `nil`이면 그 항목은 `failures`에 `unsafePath`로 기록하고 계속한다. 개별 파일의 CRC 오류는 `failures`에 기록하고 계속한다. 같은 경로가 두 번 나오면(대소문자만 다른 경우 포함) 뒤의 것을 `UniqueName`으로 번호를 붙여 푼다. 심볼릭 링크는 만들지 않고 `skippedSymlinks`로 센다.

- 위쪽 끌어다 놓기 영역: 평소 "파일이나 폴더를 여기에 끌어다 놓으세요", 호버 시 강조. `.dropDestination(for: URL.self)`로 받는다.
- 드롭 직후 **판단 결과를 분명히 표시**: `.extract`면 "압축 풀기: <파일명>", `.compress`면 "압축하기: <항목 수>개 항목". 별도 모드 전환 버튼은 없다.
- 압축 모드: `SecureField`(라벨 "비밀번호 (비워 두면 암호 없음)"), "압축" 버튼, 비밀번호가 비어 있지 않을 때만 표시되는 한 줄 경고: "ZipCrypto 방식이라 암호 강도가 약합니다. 한글 비밀번호는 윈도우 프로그램에 따라 열리지 않을 수 있으니 영문·숫자를 권장합니다."
- 해제 모드: `inspect`를 먼저 호출. 총 크기가 `Archiver.confirmBytes` 초과이거나 (총 크기 > 1GiB이고 압축 파일 대비 1000배 초과)면 "풀면 약 X가 됩니다. 계속할까요?"(`ByteCountFormatter`) 확인. 암호화되어 있으면 비밀번호 입력 시트. 틀린 비밀번호면 시트가 다시 열리고 "비밀번호가 맞지 않습니다."를 보여 준다.
- 진행 중: `ProgressView(value:)`와 현재 파일명, "취소" 버튼. 압축·해제는 `Task.detached`에서 `Archiver`를 호출하고 취소 플래그는 잠금으로 보호된 `Bool`로 공유한다.
- 완료: 결과 메시지(건너뛴 심볼릭 링크 수, 실패 항목 수 포함)와 "Finder에서 보기"(`NSWorkspace.activateFileViewerSelecting`). 오류는 `ZipError`별 한국어 문장으로 보여 준다(`unsupportedAES`는 "AES 암호화는 지원하지 않습니다.", `tooLarge`는 "4GB 이상의 파일은 지원하지 않습니다." 등).

## 자체 검토 결과

**스펙 커버리지:** 압축(NFC·플래그·제외 파일) 태스크 6·8 / 비밀번호 ZipCrypto 태스크 2·6·7 / 인코딩 자동 판별 5단계 태스크 3·7 / 해제 안전 규칙(경로, 심볼릭 링크, CRC, 틀린 비밀번호, 번호 붙이기, zip bomb 확인) 태스크 4·7·8·9 / 앱 동작(자동 판단, 백그라운드, 취소, 한국어) 태스크 8·9 / 형식 범위(deflate·store, AES 오류, 유닉스 권한, 데이터 디스크립터) 태스크 6·7 / 검증 방법(교차 검증, 악의적 경로, 큰 파일) 태스크 5~8 / dmg 배포 태스크 10. 윈도우 실제 확인은 자동화할 수 없어 README 체크리스트로 남겼다.

**계획 작성 중 정한 값(설계 문서 12절 이후 추가):**
- 테스트는 `MaczipChecks` 실행 파일로 한다(이 맥에 XCTest·Swift Testing이 없음).
- 암호화 항목의 검사 바이트는 DOS 시간 상위 바이트, 모든 항목에 데이터 디스크립터(비트 3)를 쓴다(스트리밍 쓰기를 위해).
- 단일 파일 압축 이름은 확장자를 유지한다(`보고서.hwp.zip`, macOS 기본 동작과 같음).
- 비밀번호는 UTF-8을 기본으로 쓰되, 해제할 때는 CP949 바이트도 후보로 시도한다.
- zip bomb 확인 기준은 총 해제 크기 4GiB 초과, 또는 1GiB 초과이면서 압축률 1000배 초과.
- 번들 식별자는 `dev.maczip.app`, 버전은 1.0.
